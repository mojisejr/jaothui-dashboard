# คู่มือทดสอบการเพิ่ม–แก้ไขควาย #jaothui-buffalo-error-visibility

เอกสารนี้ใช้กับรุ่นที่มี `fix/buffalo-progress-recovery` หลังนำขึ้นระบบแล้ว
รุ่นเดิมจะยังไม่มีข้อความและปุ่มใหม่ ห้ามถือว่า automated tests ยืนยันผลบน production แล้ว

## จุดที่แก้และขอบเขตหลักฐาน

- ใช้ตัวนัดเดินงานต่อร่วมกันในหน้าเพิ่มและแก้ไข โดยข้อมูลสถานะเดิมที่โหลดซ้ำจะไม่เลื่อนเวลาสั่งงานออกไปเรื่อย ๆ
- หลังเก็บคำขอและรับรูปสำเร็จ หน้าแก้ไขจะปิดหน้าต่างกรอกข้อมูลก่อนรอการตรวจ blockchain เพื่อแสดงความคืบหน้าและทางไปต่อ
- ถ้าการเตรียมงานไม่สำเร็จ ยังสั่งตรวจและเดินต่อคำขอเดิมได้ ไม่ต้องสร้างคำขอใหม่
- เพิ่มคำแนะนำการรอ เวลาในช่วงที่กำลังรอ และปุ่มคัดลอกเลขรายการ/สถานะ/หลักฐานธุรกรรม
- คงการตรวจสิทธิ์ ตัวตนควาย การป้องกันธุรกรรมซ้ำ และการรักษาช่องที่ไม่ได้แก้

Automated regression จำลองได้ว่าข้อมูลสถานะเดิมที่มาถี่ทำให้ตัวจับเวลาเดิมไม่เรียกขั้นตอนถัดไป
และหน้าต่างเดิมบังความคืบหน้าระหว่างเตรียมรายการ แต่ยังไม่ได้ยืนยันว่าเป็นสาเหตุทั้งหมดของเหตุการณ์บนมือถือจริง
รอบนี้ไม่มีการทดลองสร้างควาย แก้ข้อมูล หรือส่งธุรกรรมจริงโดย AI

## ก่อนเริ่ม

1. ยืนยันว่าเป็นรุ่นใหม่แล้ว โหลดหน้าเว็บใหม่ เลือกเจ้าหน้าที่ทดสอบทีละคน
2. ใช้ควาย/ข้อมูลจริงที่ได้รับอนุญาต บันทึกไมโครชิปและค่าเดิมก่อนแก้ ไม่ใช้ข้อมูลสมมติบนระบบจริง
3. ถ้ามีรายการค้าง ให้เปิดรายการนั้นก่อน อย่าสร้างใหม่เพื่อข้ามรายการเดิม

## แก้ไขข้อมูล

1. ค้นหาไมโครชิป ตรวจว่าเป็นควายตัวที่ต้องการ แล้วเปิดช่องที่จะแก้
2. กด “ยืนยันการแก้ไข” ครั้งเดียว รออยู่หน้าเดิม
3. หากเลือกรูป ต้องเป็น JPEG/PNG ต่ำกว่า 2,000,000 ไบต์ รูปที่รับแล้วเป็นเพียงขั้นตอนหนึ่ง
4. หลังรับคำขอ/รูปสำเร็จ หน้าต่างกรอกข้อมูลควรปิด แล้วเห็นคำแนะนำการรอ เลขรายการ และสถานะด้านล่าง
5. **เสร็จเมื่อขึ้น “แก้ไขช่องที่ร้องขอและตรวจสอบสำเร็จแล้ว” เท่านั้น** จากนั้นตรวจค่าล่าสุดและใบรับรองที่เกี่ยวข้อง ออกจากหน้าได้
6. ถ้าระบุว่าบันทึกสำเร็จแต่โหลดข้อมูลล่าสุดไม่ได้ ให้โหลดรายละเอียดอีกครั้ง ไม่กดบันทึกซ้ำ

เผื่อเวลาประมาณ 1–3 นาทีต่อช่วงที่กำลังดำเนินการ เป็นแนวทางการรอ ไม่ใช่ผลวัดหรือเวลารับประกัน
การแก้บางช่องมีหลายธุรกรรมและอาจใช้เวลารวมมากกว่า 3 นาที
ถ้ามีความคืบหน้าหรือหลักฐานธุรกรรมเพิ่ม ให้รอต่อจนข้อความสำเร็จสุดท้าย
ถ้าเกิน 5 นาทีโดยสถานะไม่คืบหน้า ให้เก็บหลักฐานด้านล่างและแจ้งผู้ดูแล ไม่สรุปว่าล้มเหลวและเริ่มใหม่เอง

## เพิ่มควาย

1. บันทึกข้อมูล → เลือกรูปและรอรับรูป → ตรวจข้อมูล → “ยืนยันข้อมูลและเตรียม Mint”
2. เมื่อพร้อม ให้กด **Mint NFT** ครั้งเดียว แล้วรอ
3. เมื่อขึ้น **“Mint NFT ยืนยันแล้ว กรุณากด Mint Metadata”** ให้กด **Mint Metadata** งานยังไม่เสร็จแม้มี Token แล้ว
4. รอจนขึ้น **“เสร็จสมบูรณ์”** และข้อความตรวจข้อมูลครบ จึงออกจากหน้าหรือเพิ่มตัวถัดไป
5. ตรวจว่าค้นหาควายที่เพิ่มได้ ข้อมูลและรูปถูกต้อง และมีเพียงรายการเดียว

เผื่อเวลารอเป็นช่วง ๆ ตามด้านบน ต้องทำครบทั้งสองปุ่ม ไม่มีการกด Mint Metadata อัตโนมัติแทนผู้ใช้

## เมื่อเน็ตหลุด/ปิดหน้า/เข้าสู่ระบบใหม่

กลับหน้าเดิม หน้าแก้ไขให้ค้นหาไมโครชิปเดิม หน้าเพิ่มให้เลือกรายการเดิม
ระบบอาจเดินงานต่ออัตโนมัติเมื่ออ่านสถานะได้ ถ้ามีปุ่ม “ดำเนินการต่อรายการเดิม” และกดได้ ให้กดครั้งเดียว
ถ้าอ่านสถานะไม่ได้ ให้ใช้ปุ่มโหลดสถานะ/รายการอีกครั้งก่อน อย่าส่งคำขอใหม่
การปิดหน้าไม่ได้รับประกันว่างานจะทำต่อจนจบเองในเบื้องหลัง
หากแก้ไมโครชิปแล้วค้นหาเลขเดิมไม่พบ ให้ตรวจเลขใหม่ด้วยและส่งเลขรายการให้ผู้ดูแลก่อนเริ่มใหม่

## ตารางยอมรับผลของทีม

ทดสอบเฉพาะการเปลี่ยนแปลงจริงที่เจ้าของข้อมูลอนุญาต ไม่ต้องเปลี่ยนทุกช่องของควายตัวเดียวเพื่อทดสอบ

| งาน | สิ่งที่ต้องตรวจหลังข้อความสำเร็จ |
| --- | --- |
| รูปควาย | รูปใหม่ในรายละเอียดและใบรับรอง ช่องอื่นและ DNA เดิมยังอยู่ |
| ชื่อ/ส่วนสูง/เลขใบรับรอง/รายละเอียด/ระดับ/DNA | ช่องที่แก้ถูกต้อง ช่องอื่นไม่เปลี่ยน |
| วันเกิด/แหล่งกำเนิด/สี/เพศ | ค่าถูกต้อง DNA พ่อแม่และช่องอื่นไม่ถูกล้าง |
| ไมโครชิป | ค้นหาเลขใหม่และเปิดใบรับรองใหม่ได้ เป็น NFT ตัวเดิม ไม่เกิดควายซ้ำ |
| พ่อ/แม่ | ความสัมพันธ์ที่เลือกถูกต้อง การแก้เพียงฝั่งเดียวรักษาอีกฝั่งไว้ |
| เพิ่มควาย | ทำครบ NFT และ Metadata ค้นหาได้ รูปและข้อมูลครบ ไม่สร้างซ้ำ |
| หลุดแล้วกลับมา | เลขรายการ/Token เดิม ตรวจผลก่อนส่งต่อ ไม่เริ่มเพิ่มควายซ้ำ |

## ถ้าไม่สำเร็จ ส่งอะไรกลับ

1. กด **“คัดลอกข้อมูลรายการเพื่อแจ้งผู้ดูแล”** ส่งข้อความที่คัดลอกมา (เลขรายการ สถานะ เวลา และเลขธุรกรรมถ้ามี)
2. ถ้ามี error ให้กด **“คัดลอกรหัสอ้างอิง”** ส่งมาด้วย
3. แนบภาพหน้าจอที่เห็นสถานะและ error พร้อมบอกไมโครชิป ช่องที่แก้ เวลาเริ่ม และรอนานเท่าไร
4. บอกมือถือ/คอมพิวเตอร์ เบราว์เซอร์ และมีการปิดหน้า สลับแอป หรือเน็ตหลุดหรือไม่
5. ไม่ส่งรหัสผ่าน token สำหรับเข้าสู่ระบบ หรือข้อมูลลับอื่น

ไม่มีข้อความสำเร็จสุดท้าย = ยังไม่ยืนยันว่าทำครบ แม้รับรูปแล้วหรือมี transaction hash แล้ว

## รอบแก้การตรวจไฟล์หลังเผยแพร่

รุ่น `fix/buffalo-publication-readback` ตรวจ URL เดิมก่อน หากข้อมูลยังไม่ตรง จะอ่าน URL ที่ผูกกับ SHA256 ของไฟล์ซ้ำหนึ่งครั้ง โดยยังต้องตรวจ bytes ตรงกันทุกครั้ง ไม่ข้ามการตรวจความถูกต้อง
ถ้ายังไม่ผ่าน จะแจ้ง `PUBLIC_ASSET_READBACK_PENDING` ในขั้นเผยแพร่แทน `ADAPTER_UNAVAILABLE` และเก็บรายการเดิมไว้ให้ทำต่อ
หลังทะเบียนอัปเดต URL รูปใน dashboard จะเปลี่ยนเวอร์ชันตามข้อมูลที่บันทึกแล้ว เพื่อให้โหลดรูปใหม่

เคสฟ้าราชสีห์ NFT1347 ใช้ operation เดิม `4de314cf-b653-4ce0-857a-8974cce479f6`:
หลังนำรุ่นใหม่ขึ้น production ให้โหลดหน้าใหม่ ค้นหา `764040226601866` แล้วกด “ดำเนินการต่อรายการเดิม” หนึ่งครั้ง รอข้อความสำเร็จสุดท้ายและตรวจรูปใหม่
ไม่ต้องอัปโหลดหรือสร้างคำขอเปลี่ยนรูปใหม่ ทั้ง batch และ uri ของรายการนี้มีธุรกรรมยืนยันแล้ว
หากไม่จบ ส่งรายงานรายการและรหัสอ้างอิงล่าสุดกลับมา ผู้ดูแลจะตรวจผลอ่านไฟล์ (ชื่อไฟล์ สถานะ HTTP และ hash) ที่บันทึกเพิ่มไว้
