## หน้าที่ของผู้ดูแล
ตรวจการเชื่อมต่อ สิทธิ์เขียน และระบบส่งข้อความเมื่อทีมแจ้งปัญหา ที่นี่ระบุ **ชื่อตัวแปรเท่านั้น** ไม่เก็บค่าหรือ credential การเปลี่ยนค่าต้องทำตามแผนปล่อยระบบและตรวจหลัง redeploy

## ฝั่ง Dashboard
- `JAOTHUI_COMPETITION_ADMIN_API_BASE_URL` — ที่อยู่ API หลังบ้านของ event
- `JAOTHUI_COMPETITION_ADMIN_API_KEY` — key server-only สำหรับเรียก API

## ฝั่ง Event
- `JAOTHUI_COMPETITION_ADMIN_API_KEY` — key เชื่อมต่อที่ต้องตรงกับ Dashboard
- `SANITY_API_WRITE_TOKEN` — สิทธิ์เขียนข้อมูลของ Event เก็บไว้เฉพาะ server
- `JAOTHUI_COMPETITION_ADMIN_WRITES_ENABLED` — อนุญาตเขียนผ่าน API ใหม่
- `COMPETITION_LEGACY_ADMIN_DISABLED` — ย้ายทางเข้าและปิด API admin เดิม
- `JAOTHUI_COMPETITION_DASHBOARD_URL` — ทางเข้าหลังบ้านใหม่
- `COMPETITION_LINE_NOTIFICATIONS_ENABLED` — ควบคุมการส่ง LINE จริง

## ขอบเขตการหยุดฉุกเฉิน
สวิตช์เขียนและ LINE **ไม่ใช่ปุ่มปิดรับสมัครทั่วไป** และไม่ย้อนข้อมูลที่บันทึกไปแล้ว ผู้ดูแลต้องรักษา legacy cutover และประวัติเดิมตาม runbook ปล่อยระบบ ไม่ให้ทีมปฏิบัติงานเปลี่ยนค่าตั้งเอง

## หลักฐานและขอบเขตของเล่ม
ฉบับ 0.2 จัดทำ 26 ตุลาคม 2569 จาก UI และโค้ดที่ตรวจไว้ ภาพใช้ local/dev และปิดส่งจริง ภาพสถานะไม่ยืนยันการส่งถึงคนจริงหรือการเปิดอ่าน ผู้ดูแลตรวจฉบับปัจจุบันก่อนใช้กับงานสำคัญ

ยังรอให้ผู้เริ่มใช้งานลองอ่านและทำตาม จึงไม่อ้างว่าอ่านครั้งเดียวทำได้ทุกคน ต้นฉบับและรายการตรวจอยู่ในโฟลเดอร์หนังสือเพื่อแก้ไขและสร้างซ้ำได้
